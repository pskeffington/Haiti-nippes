# Archived Research Note: Mesh Hardware Proof-of-Concept Planning

## Status

This file is retained as a historical research-planning artifact. It is **not an active deployment plan** and should not be used to design clinic-node placement, relay placement, field-worker communications procedures, operational channels, range tests, or healthcare deployment workflows.

The current `Haiti-nippes` repository is a public, civic-facing regional public-health research scaffold. Its active scope is source-bounded secondary-data research, geospatial context, WASH resilience, health access, food security, infrastructure fragility, and reproducible documentation.

## Historical research value

Earlier versions of this note explored whether synthetic Meshtastic interfaces, message objects, adapter boundaries, and metadata-only logs could be used as a software-engineering teaching and methods exercise. That synthetic software work may remain useful for reproducibility, interface design, and public-safe testing.

The earlier progression from local devices to range testing and Nippes-specific deployment modeling is superseded and outside the present public research boundary.

## Current boundary

Appropriate work in this repository is limited to:

- synthetic or memory-only communications fixtures;
- software-interface and schema testing;
- metadata-only examples with no real participants, sites, or operational identifiers;
- reproducible programming exercises; and
- literature or methods review concerning resilient communications as a research topic.

Do not use this repository to:

- plan real radio deployments;
- select or rank clinic, relay, gateway, or worker-device locations;
- define operational channel procedures or key-management practice;
- conduct or document field range tests tied to real sites;
- transmit patient, worker, or private operational information; or
- treat a successful synthetic or bench test as evidence of healthcare-system readiness.

## Evidence boundary

A synthetic test can demonstrate that a software object, parser, adapter, or logging path behaves as specified. It does not establish communications coverage, reliability under field conditions, clinical usefulness, institutional authorization, emergency readiness, or deployment suitability.

## Historical-use rule

If older commits are consulted, treat hardware progression, live-device testing, range testing, and deployment-model language as superseded research-history material rather than current instructions or project status.
